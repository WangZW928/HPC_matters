## 🔍 根因假设与候选否决

先检查 git status，发现已有大量未提交生产实现、测试和报告；保存起始内容快照、
status、diff 及三个真实 executable，后续只恢复自己引入的候选内容。阅读最新两份
[M2 积分 RHS 报告](./AMReX_M2_积分RHS统一与首步压力门_20261011.md)、
[M2 面权威报告](./AMReX_M2_面守恒权威生产增量_20261011.md)，并核对任务清单、
README、迁移/规格/审阅、production projector/shared stencil 和现有 audit/CTest。

既有 frozen-RHS replay 表明同 RHS 的 Phi 差仅0–1.33e-16，这是上一轮证据，本轮
没有重新运行该 harness。此次实际矩阵完全复现首步差异。根因假设仍是初始投影
留下约1e-18面状态舍入差，经小 dt 的约束 RHS 放大；不能据此认定某一个 reduction
或 gauge 是唯一原因，更不能减掉既有面散度、修改 datum 或调整停止条件来过门。

源码的切向四值表达式按 `((a-b)+c)-d` 求值，存在先加入绝对标量再相消的问题。
以本轮基线 CPU initial Phi 的真实1024个 cell 为输入，用90位 Decimal 对输入
double 的精确值计算两侧差分之和：d0/t1 的旧/配对 RMS 舍入误差分别为
8.91246e-19 / 8.41424e-19，d1/t0 为9.99304e-19 / 9.83183e-19。
这只证明局部四值算术可改善，不是完整投影误差解释或跨后端保证。

尝试一：只在 opt-in 路径中将切向 stencil 改为 `(a-b)+(c-d)`，压力 full/cross
与 component viscosity 继续调用同一 helper；默认保留原表达式。尝试二在该 opt-in
cross contribution 再使用显式 `std::fma`，统一一次舍入的乘加。候选曾在既有
face-authority 契约内加入精确 dyadic 相消 witness，实际 host/device 运行通过；
该临时 witness 随候选撤回，最终没有新增 CTest、输入 selector 或数值矩阵。

## 🔧 最终保留的生产代码与回退

[AVWiSProjection.cpp](../amrex_port/src/AVWiSProjection.cpp) 的 `project_mapped()`
在 ghost freshness 和初始 divergence 计算之后，且 Ucat 不发生写入的尺度计算块中，
对 `face_authoritative` 求一次三个组件的全局最大范数。后面的 d/c 双循环取该值，
仍逐项执行原公式与同一顺序：

$$
s=1+\sum_{d=0}^{2}\sum_{c=0}^{2}
\frac{\|Ucat_c\|_\infty\,\|\nabla\xi_{3d+c}\|_\infty}{h_d}.
$$

仅 Ucat 的 norm scan/reduction 由9变3，metric 的9次保持；这个尺度块总计由18
变12。不重排浮点求和，不缓存 metric norm，不改变 `64*epsilon*s` skip 门。
旧 `experimental_dual_state` 分支逐次执行原本的 norm/reduction；RHS、DG、datum、
full residual <=1e-11、inner <=1e-12、outer/inner 上限和 candidate commit 不变。

三个 Real 只活在当前函数调用中，没有新增 MultiFab、持久 workspace、metric epoch
状态、checkpoint 字段或 host/device copy。失败重试重新求值，不可能消费旧缓存。
数值失败仍保留原 fatal 语义：current P/Ucat/Nvert 不提交，predictor/history/Phi
可变化；没有整个 advance rollback 声明。

[静态检查](../amrex_port/tests/static_contract_check.sh) 仅补 opt-in gate、缓存取值和
默认归约分支的存在性检查；不将字符串检查当作数值验收。最终生产代码差异仅
一个 cpp，另一个修改文件为 static checker；shared stencil、deferred solve、viscosity
及既有 face-authority contract 文件与本轮起点逐字节一致。恢复时显式更新依赖文件
mtime 并重新编译，避免恢复旧时间戳后误用候选 object。

回退本轮只需应用归档的本轮增量逆 patch，不能用 `git checkout/reset` 覆盖用户
之前的未提交内容。切回旧 state/pressure pair 仍是已有功能回退接口。
