# AMReX P0/P1 测试计划与结果（2026-08-21）

## 结论

本次完成的是 AMReX `26.04`（git `9219ba416b7ba2073dd1b12bf19fdce27391f17b`）的 P0/P1 **框架契约**验证；未修改 `CFD/vwis2.0/vwis2.0` 旧 solver。CPU MPI、单 rank CUDA 都已实际通过。`advance_one_step()` 仍是 no-op，因此本报告不作任何 CFD 数值精度、守恒、速度/压力、LES、IBM、FSI 或旧算例等价性声明。

- CPU MPI：OpenMPI 4.1.6；AMReX 以 `AMReX_MPI=ON`、`/usr/bin/mpicxx` 成功构建并安装。static contract PASS，CTest 3/3 PASS；`p1_contract.in` 在 `mpiexec -n 2` 和 `-n 4` PASS，`p1_multibox.in` 在 `-n 2` PASS。
- CUDA：RTX 4060 Laptop GPU（driver 566.36 / CUDA reported 12.7）在 WSL 可用；`nvcc` 12.6.85，AMReX 以 CUDA arch 89 成功 build/install，port 完成 nvcc 编译和 CMake device link。CUDA CTest 3/3 PASS，直接运行 `p1_contract.in` PASS，且 AMReX 报告初始化 1 个 CUDA device。
- CUDA-aware MPI：**未测试**。CUDA build 是 `AMReX_MPI=OFF`，MPI build 是 CPU backend；不能从上述两类成功推断 GPU-aware halo 或多 GPU/rank 正确性。

## 范围与 runtime contract

`p1_contract.in` 的制造场检查覆盖 14 个 P1 字段的 cell/face layout、components、`nGrow` 及 face `IndexType`；零初始化；24-box、2 ghost、三向周期制造场的 inter-box/MPI halo；non-periodic ghost 仍为 sentinel（没有 physical BC functor）；以及 schema-only metadata manifest。该检查的 `FillBoundary` 成功不表示物理边界条件已实现。

AMReX MPI package exports a C MPI dependency. Therefore the minimal port fix was `project(vwis_amrex_port LANGUAGES C CXX)`; without C language enablement the MPI consumer configure cannot resolve the package dependency. CUDA consumes the package's public device annotations by enabling CUDA, compiling kernel-bearing sources with nvcc, and setting `CUDA_RESOLVE_DEVICE_SYMBOLS` for device link.

CUDA build hygiene: before building, process inspection found no pre-existing build for `/tmp/vwis-amrex-26.04-cuda-make-build`; the retained completion pass was exactly `cmake --build /tmp/vwis-amrex-26.04-cuda-make-build --parallel 1`. A transient duplicate launcher was detected and stopped immediately; all retained build/install evidence below comes from the original serial pass, and no duplicate build remains.

```bash
# CUDA AMReX retained tree (already configured with arch 89)
cmake --build /tmp/vwis-amrex-26.04-cuda-make-build --parallel 1
cmake --install /tmp/vwis-amrex-26.04-cuda-make-build

cmake -S CFD/vwis2.0/amrex_port -B /tmp/vwis-amrex-port-26.04-cuda-build \
  -G 'Unix Makefiles' -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON \
  -DAMReX_DIR=/tmp/vwis-amrex-26.04-cuda-install/lib/cmake/AMReX \
  -DVWIS_AMREX_EXPECTED_VERSION=26.04 -DCMAKE_CUDA_ARCHITECTURES=89
cmake --build /tmp/vwis-amrex-port-26.04-cuda-build --parallel 1
ctest --test-dir /tmp/vwis-amrex-port-26.04-cuda-build --output-on-failure -V
```

Build evidence: AMReX cache records `AMReX_GPU_BACKEND:STRING=CUDA`, `AMReX_CUDA_ARCH:STRING=89`, `AMReX_MPI:BOOL=OFF`, and nvcc. The port build output contains `Linking CUDA device code .../cmake_device_link.o` followed by `Built target vwis_amrex_skeleton`.

## Remaining limits

P1 is single-level Cartesian scaffolding: no physical BC functor, no plot/checkpoint payload or restart, and no RHS/projection/LES/IBM/FSI/AMR. Keep one reusable CPU, MPI and CUDA build/install pair; do not treat build or framework-contract success as an old CFD solver validation. A future CUDA+MPI build must separately validate rank placement, device-resident halo exchange and CUDA-aware MPI.
