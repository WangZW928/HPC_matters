# Red-Black Tree（红黑树）C++ 教程

红黑树是一种**自平衡二叉搜索树**。它在普通二叉搜索树的基础上，为每个结点增加一个颜色位：红色或黑色，并通过一组规则限制树的形状，使树的高度始终保持在 `O(log n)` 级别。

普通二叉搜索树如果按有序数据插入，可能退化成链表：

```text
1
 \
  2
   \
    3
     \
      4
```

此时查找、插入、删除都会退化为 `O(n)`。红黑树通过**旋转**和**重新着色**维持平衡，让这些操作稳定保持 `O(log n)`。

## 1. 基本原理

红黑树仍然满足二叉搜索树性质：

```text
左子树 key < 当前 key < 右子树 key
```

它额外维护颜色约束。颜色并不是为了表示数据含义，而是为了控制树的最长路径不会超过最短路径的两倍。因此红黑树不是“绝对平衡”，而是“近似平衡”。

### 为什么自平衡很重要

如果树不平衡，高度可能是 `n`：

```text
查找路径：1 -> 2 -> 3 -> 4 -> 5
```

如果树保持平衡，高度约为 `log2(n)`：

```text
        3
      /   \
     2     5
    /     /
   1     4
```

数据规模越大，差异越明显。红黑树常用于 `std::map`、`std::set` 这类需要有序、动态插入删除的数据结构。

### 红黑树与 AVL 树比较

| 特性 | 红黑树 | AVL 树 |
|---|---|---|
| 平衡程度 | 近似平衡 | 更严格平衡 |
| 查询效率 | `O(log n)`，通常略逊于 AVL | `O(log n)`，高度更低 |
| 插入删除 | 旋转次数相对少，适合频繁修改 | 可能需要更多旋转 |
| 常见用途 | `map` / `set` / 内核调度结构 | 查询密集型场景 |

简单理解：**AVL 树更“端正”，红黑树更“务实”**。如果插入删除很多，红黑树通常更合适。

## 2. 红黑树五条性质

红黑树必须满足以下五条性质：

1. 每个结点要么是红色，要么是黑色。
2. 根结点是黑色。
3. 所有叶子结点 `NIL` 是黑色。这里的 `NIL` 是空孩子的哨兵结点，不存储真实数据。
4. 如果一个结点是红色，那么它的两个孩子都是黑色。也就是说，不能出现连续两个红结点。
5. 从任意结点到其所有后代 `NIL` 叶子的路径上，黑色结点数量相同。这个数量称为黑高（black-height）。

示意图：

```text
             10(B)
           /       \
        5(R)       20(R)
       /   \       /   \
   NIL(B) NIL(B) NIL(B) NIL(B)
```

其中 `(B)` 表示黑色，`(R)` 表示红色。所有 `NIL` 都被视为黑色。

## 3. 实现步骤

本教程的 C++ 实现采用 key-only 版本，行为类似简化版 `std::set`。为了让删除修复更清晰，代码使用一个共享的黑色哨兵 `NIL`。

### 3.1 结点结构

每个结点保存：

- `key`：键值
- `color`：颜色
- `parent`：父结点
- `left` / `right`：左右孩子

```cpp
enum class Color {
    RED,
    BLACK
};

template <typename Key>
struct Node {
    Key key;
    Color color;
    Node* parent;
    Node* left;
    Node* right;
};
```

概念图：

```text
       parent
         |
       node
      /    \
   left    right
```

### 3.2 旋转

旋转只改变局部指针关系，不破坏二叉搜索树的中序顺序。

#### 左旋 left-rotate

对 `x` 左旋时，`x` 的右孩子 `y` 上升，`x` 变成 `y` 的左孩子。

旋转前：

```text
      x
     / \
    A   y
       / \
      B   C
```

旋转后：

```text
        y
       / \
      x   C
     / \
    A   B
```

注意：`B` 原来大于 `x` 且小于 `y`，旋转后作为 `x` 的右子树，仍满足二叉搜索树性质。

#### 右旋 right-rotate

右旋是左旋的镜像操作。

旋转前：

```text
        y
       / \
      x   C
     / \
    A   B
```

旋转后：

```text
      x
     / \
    A   y
       / \
      B   C
```

### 3.3 插入

红黑树插入分两步：

1. 按普通二叉搜索树规则插入新结点。
2. 新结点先染成红色，然后执行 `insertFixup` 修复红黑性质。

为什么新结点先染红？因为插入红结点不会直接改变路径上的黑色结点数量，只可能造成“父红子红”的冲突，修复范围更小。

#### 插入修复 Case 1：叔叔结点是红色

```text
        G(B)
       /    \
    P(R)    U(R)
    /
  Z(R)
```

处理方式：

- `P` 和 `U` 染黑
- `G` 染红
- 把 `G` 当作新的 `Z` 继续向上修复

处理后：

```text
        G(R)
       /    \
    P(B)    U(B)
    /
  Z(R)
```

#### 插入修复 Case 2：叔叔结点是黑色，且新结点是“内侧孩子”

以内侧右孩子为例：

```text
        G(B)
       /
    P(R)
       \
       Z(R)
```

先对 `P` 左旋，转换成 Case 3：

```text
        G(B)
       /
     Z(R)
     /
   P(R)
```

#### 插入修复 Case 3：叔叔结点是黑色，且新结点是“外侧孩子”

```text
        G(B)
       /
    P(R)
    /
  Z(R)
```

处理方式：

- `P` 染黑
- `G` 染红
- 对 `G` 右旋

处理后：

```text
      P(B)
     /    \
  Z(R)    G(R)
```

右侧插入的情况完全对称：把“左”与“右”互换即可。

### 3.4 删除

删除比插入复杂，因为删除黑色结点可能破坏黑高。

红黑树删除也分两步：

1. 按二叉搜索树删除规则移除目标结点。
2. 如果实际被移走的是黑色结点，执行 `deleteFixup`。

普通二叉搜索树删除有三种情况：

```text
1. 没有左孩子：用右孩子替换自己
2. 没有右孩子：用左孩子替换自己
3. 有两个孩子：用右子树最小结点后继替换自己
```

有两个孩子时：

```text
删除 z，找 z 右子树中的最小结点 y

        z
       / \
      A   R
         /
        y
```

用 `y` 替换 `z` 的位置后，仍然保持中序有序。

### 3.5 删除修复的 4 种情况

删除修复中，`x` 表示带着“少一个黑色”问题的结点，`w` 表示 `x` 的兄弟结点。下面以 `x` 是左孩子为例，右孩子情况完全对称。

#### 删除修复 Case 1：兄弟 `w` 是红色

```text
       P(B)
      /    \
    x      w(R)
          /   \
       A(B)  B(B)
```

处理方式：

- `w` 染黑
- `P` 染红
- 对 `P` 左旋

这样可以把问题转换成兄弟为黑色的情况。

```text
        w(B)
       /    \
    P(R)    B(B)
   /   \
  x    A(B)
```

#### 删除修复 Case 2：兄弟 `w` 是黑色，且 `w` 的两个孩子都是黑色

```text
       P(?)
      /    \
    x      w(B)
          /   \
       A(B)  B(B)
```

处理方式：

- `w` 染红
- `x` 上移到 `P`

含义是把 `w` 子树贡献的一个黑色向上“借走”，继续检查父结点。

#### 删除修复 Case 3：兄弟 `w` 是黑色，`w` 的远侧孩子是黑色，近侧孩子是红色

```text
       P(?)
      /    \
    x      w(B)
          /   \
       A(R)  B(B)
```

处理方式：

- `A` 染黑
- `w` 染红
- 对 `w` 右旋

转换成 Case 4：

```text
       P(?)
      /    \
    x      A(B)
             \
             w(R)
               \
               B(B)
```

#### 删除修复 Case 4：兄弟 `w` 是黑色，且 `w` 的远侧孩子是红色

```text
       P(?)
      /    \
    x      w(B)
          /   \
       A(?)  B(R)
```

处理方式：

- `w` 继承 `P` 的颜色
- `P` 染黑
- `B` 染黑
- 对 `P` 左旋
- 修复结束

```text
        w(?)
       /    \
    P(B)    B(B)
   /   \
  x    A(?)
```

### 3.6 查找

查找与普通二叉搜索树完全相同：

```text
当前 key == target：找到
target < 当前 key：去左子树
target > 当前 key：去右子树
```

示意：

```text
查找 15

        20
       /
     10
       \
       15  <- found
```

时间复杂度为 `O(log n)`。

## 4. 调用方式

本项目中的 `red_black_tree.cpp` 提供一个模板类：

```cpp
template <typename Key, typename Compare = std::less<Key>>
class RedBlackTree;
```

### API 参考

| API | 说明 | 复杂度 |
|---|---|---|
| `bool insert(const Key& key)` | 插入键。成功返回 `true`，重复键返回 `false` | `O(log n)` |
| `bool find(const Key& key) const` | 查找键是否存在 | `O(log n)` |
| `bool erase(const Key& key)` | 删除键。成功返回 `true`，不存在返回 `false` | `O(log n)` |
| `std::size_t size() const` | 返回结点数量 | `O(1)` |
| `bool empty() const` | 判断是否为空 | `O(1)` |
| `std::vector<Key> inorder() const` | 返回中序遍历结果 | `O(n)` |

### 示例用法

```cpp
RedBlackTree<int> tree;

tree.insert(10);
tree.insert(20);
tree.insert(15);

if (tree.find(15)) {
    std::cout << "15 exists\n";
}

tree.erase(20);

for (int x : tree.inorder()) {
    std::cout << x << ' ';
}
```

编译运行：

```bash
g++ -std=c++17 -Wall -Wextra -pedantic red_black_tree.cpp -o red_black_tree
./red_black_tree
```

示例输出：

```text
插入: 10 20 30 15 25 5 1 8
中序遍历: 1 5 8 10 15 20 25 30
结点数量: 8
查找 15: 存在
删除 20 和 5
删除后中序遍历: 1 8 10 15 25 30
结点数量: 6
再次查找 20: 不存在
```

## 5. 小结

红黑树的核心不是“记住所有情况”，而是理解两个动作：

- **重新着色**：调整局部黑高或消除连续红结点。
- **旋转**：改变局部树形，让二叉搜索树性质保持不变，同时恢复红黑性质。

插入主要处理“连续红结点”，删除主要处理“黑高减少”。掌握这两点，再配合 ASCII 图理解 3 种插入修复和 4 种删除修复，就能读懂大多数红黑树实现。
